## 3. Security and policy-window semantics

- F2's `f2-history-365d-v1` baseline/delta is **not reused as a 90-day value**. The service consults F2 only for its verified, non-executable run/fact/selected-observation/same-patient history exclusions, loads the same bounded patient history under a fresh SQLite lock and runs `compare_explicit_current_with_history(... baseline_lookback_days=90)`. A value 180 days before current is allowed in F2 but **not** the 90-day policy; output is `no_baseline`, no imputed value. F0-selected zero current yields no comparisons and `no_current_selected`; 7..20 fails closed, never truncates.
- The official R3-A policy `demo_review_policy.yaml` is an **offline reference only**: canonical LF SHA-256 `f3bdad3f6a958b65b50598910cc91501dcc53ca210ff90d2e09b14695cb6bd36`; uniform Windows CRLF canonicalizes to LF; mixed/bare CR, duplicate YAML keys, invalid hash/catalogue/VI switch and unapproved version are rejected. `validate_demo_policy` alone never activates a policy. This first slice additionally binds the run to the reference **2026-11-14T12:00:00Z** fixture clock. No caller can override policy, baseline or blocker count.
- The first F2 read, locked RB1 read, and final F2 read are **separate SQLite transactions**; they do **not** form an atomic source-and-file snapshot. All three check stored doctor/patient scope and F1 current fingerprints (RB1 inspect calls F1 locked preflight); final F2 evidence equality/re-pin detects interval changes before the preview is returned where observable. This is **not permission for a later consumer to execute anything**: any future rule/write executor must perform its own fresh verification and exact metadata/bytes/identity checks in its own controlled transaction. The OS filesystem is not atomically locked by SQLite.
- Historical exclusions are explicit and never used as baselines. Self-reported remains `self_reported_validated`; mixed trust is derived, not sent by caller. Unmapped document-only facts do not become observation measurements. Historical terminal original `VI-002` stays OPEN even when properly excluded and separately selected recovery passes F1.
- No `evaluate_demo_review_rules`, `CandidateReviewFlag`, DR activation, `review_item`/`evidence_link`, `run.status` mutation, audit write, graph, agent, LLM, API, frontend, task, notification or clinical content.
