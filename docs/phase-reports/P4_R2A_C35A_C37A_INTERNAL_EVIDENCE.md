## Security and trust boundary (what is actually proven)

1. `inspect_selected_evidence` accepts an internal `Principal`, not a public/agent/API request. In addition to checking stored active doctor role and assigned synthetic patient via existing P4 projections, it binds `principal.session_id` to an actual unrevoked, unexpired `UserSession` of the **same user** at injected `as_of_utc`. A serializable or user-constructed `Principal` alone never proves token possession; this function requires the caller to derive the principal from a verified session. The session existence check is **defence in depth**, not a substitute for real auth middleware.
2. All selectors are explicit and bound to selected stored patient records, then checked. Foreign/missing selected observations return neutral 404; foreign/missing selected documents likewise 404. Duplicates/caps/error inputs fail closed. An invalid documented source cannot be treated as a valid selected current. A doc-derived history source is only eligible when its source fact/doctor decision passes existing SQLite lineage validation, its document is selected, and that selection's P4 preflight is clear. A self-report remains `self_reported_validated`. Selected source exclusions are typed by reason, not silently promoted or counted as a second source.
3. Stored verification_issue states (`open`, `resolved`, `superseded`) are **observed**; this reader does **not** invoke P3's writer `sync_issues`, change issue states or re-run full VI-001..006. Selected document preflight is a separate **candidate only**; unresolved source-text authenticity or a terminal original cannot be automatically cleared by later recovery.
4. The pure comparator does not guess history from current; the reader provides an explicit bounded history selection. The comparator returns a typed `not_admissible` + `skip_reason` for rejected/wrong-unit/future current rows, excludes invalid historical baselines and selects most-recent timestamp **strictly before** the current in the 0–365-day lookback. Cross-patient, duplicate and overflow fail closed. Trust basis is based on both supplied labels, never promotes a self-report.
5. **Single ORM Session and `no_autoflush` are not a serializable or durable source snapshot guarantee.** This PR does not implement SQLite writer exclusion, cross-transaction snapshot versioning, immutable actual workflow selected-set binding, source-file hash re-reading or stale/competing writer detection. An externally controlled read-transaction/isolation level and a real run ledger must be reviewed separately. Results are invalid for any later mutation or separate transaction. This is a deliberate partial **R2-A stage A** component, not complete end-to-end “trusted run evidence”.
6. `C-37A` is represented by a **non-evaluable inspection boundary**. The future `EvaluableReviewEvidenceV2` must be a server-produced run-bound input and cannot be built from this object while `run_gate_completed=False`. No policy object, caller-supplied `blocking_fact_count`, or fabricated `doctor_verified` token can grant rule access. Neither `TOOL_CONTRACTS.md` `3.5 nor `3.7 is silently modified in this PR.
